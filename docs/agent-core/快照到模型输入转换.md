# 快照到模型输入的转换 — snapshot.js 产出与 Jev 请求体之间的处理逻辑

> 回答一个问题：snapshot.js 获取的页面结构与实际发给 Jev 模型的内容**并不相同**，中间做了哪些处理？
> 源码依据：`jev_ultrafast/model.py`（`choose` L81-148、`action_space` L48-78）、`jev_ultrafast/agent.py`（history 账本）。
> 关联文档：[TypeSafe协议交互详解.md](./TypeSafe协议交互详解.md)（请求体的协议层解读）、[snapshot观察契约职责.md](./类的职责/snapshot观察契约职责.md)（快照的生产侧）、[双模型联动机制.md](./双模型联动机制.md)（第 4 节两种模型的视野对照）。

---

## 1. 🗺️ 全景：一份快照的四段旅程

```text
snapshot.js 产出（page dict）
     │
     │ ① 裁剪：丢掉执行/守卫的"私产"字段
     │ ② 重组：扁平动作 → 一节点一索引的元素表（action_space, model.py:48-78）
     │ ③ 包装：元素表 + 历史投影 → state + questions（model.py:81-117）
     │ ④ 回程翻译：模型答案（目标索引）→ 动作 id（model.py:120-148）
     ▼
systemone 请求体 / decision
```

快照是"观察"，请求体是"决策面"——两者之间隔着一整层**范式转换**，即 AGENTS.md 三段式 `page → indexed elements → operation + target` 的第二段。

---

## 2. ✂️ ① 裁剪：哪些字段根本不进模型

| snapshot 产出 | 是否发给模型 | 去向 |
|---|---|---|
| `rect`（每个动作的几何坐标） | ❌ | 永不进模型——几何只在执行瞬间重新解析（`browser.py:149`） |
| `node`（节点身份整数） | ❌ | 代码私产，执行期 `nodes.get(id)` 取真实元素 |
| `id`（"e1"/"e2"…） | ❌ | 执行层动作编号；choice 答案翻译回来才用它 |
| `marker` / `page_key` / `guards` | ❌ | 守卫材料，Python 侧新鲜度比对用 |
| `fingerprint` / `screenshot` | ❌ | act 守门用；截图模型不消费 |
| `scroll` / `w` / `h` / `omitted_actions` | ❌ | 丢弃 |
| `url` / `title` / `text` | ✅ | **唯一大体量透传**（text ≤6000 字符） |
| `actions` | ⚠️ | 不直接发，先重组（第 3 节） |

裁剪原则一句话：**模型只见"可选择的语义"，不见"执行的机械"**。

---

## 3. 🔧 ② 重组：actions → elements（变化最大的一步）

`action_space()`（model.py:48-78）把扁平动作列表重构为模型友好的形态，五个动作：

1. **一节点一索引**：同一 combobox 的 `fill` 与 `click` 两条动作（"Where from?" 与 "Open Where from?"）合并为一个元素 `{index:"2", operations:["TYPE_TEXT","CLICK"]}`——动作条数减少，元素语义凸显；
2. **label 规整**：select 动作的 `"Cabin → Business"` 切成字段名 `"Cabin"` + 选项 `"Business"`（`label.split(" → ")[0]`）；
3. **选项摊平**：select 的每个未选项变成复合目标键 `"4:2"`（元素 4 的第 2 项），登记进元素的 `options` 数组；
4. **值字段精选**：只保留 `role/value/checked/selected/expanded`；
5. **controls 分离**：WAIT/SCROLL_UP/SCROLL_DOWN 从动作流抽出，仅作 operation 头候选（不指向元素，没有目标头）。

**一个元素的三级形态变化**（combobox 例）：

```text
snapshot: {id:"e2", node:7, role:"combobox", label:"Where from?",
           kind:"fill", value:"", rect:{x:5,y:8,w:120,h:30}}
     ↓ 重组
elements: {index:"2", label:"Where from?", role:"combobox",
           value:"", operations:["TYPE_TEXT","CLICK"]}
     ↓ 包装进两道题（同一索引，两种面貌）
type_text_target.criteria: {"2": {element:"[2] Where from?", current_value:"", role:"combobox"}}
click_target.criteria:     {"2": {element:"[2] Open Where from?", current_value:"", role:"combobox"}}
```

select 元素的三级形态：

```text
snapshot: {id:"e9", node:12, kind:"select", label:"Cabin → Business", value:"business",
           current_value:"Economy", ...}
     ↓ 重组
elements: {index:"4", label:"Cabin", value:"Economy", role:"combobox",
           operations:["SELECT"], options:[{index:"4:1", label:"Cabin → Economy", ...}, ...]}
     ↓ 包装
select_target.criteria: {"4:1": {element:"[4] Cabin → Economy", current_value:"Economy", ...}, ...}
```

## 4. 📦 ③ 包装：组装成"考卷"（choose, model.py:81-117）

| 请求体部分 | 来源与处理 |
|---|---|
| `state.page` | 快照页面五字段取其三：url/title/text（text 再保险截断 `[:6000]`） |
| `state.elements` | action_space 重组产物，直接嵌入 |
| `state.recent_actions` | **历史投影**：history 最近 10 条，仅取 4 字段（action/kind/text/page_changed）——原始账本每条约 20 字段（概率/置信度/双模型延迟/usage/双时刻戳…）全部不进模型 |
| `questions.operation` | criteria = 操作名 → 固定说明文案（3 种操作说明 + controls 的 label + DONE/BLOCKED 文案）；instructions = goal + NEXT_ACTION 全文 |
| `questions.<op>_target` | 每种**非空**操作一个头；criteria = 目标索引 → 元素描述（`"[index] label"` 字符串化 + current_value + role/checked/selected/expanded）；instructions = goal + 操作假设 + [NEXT_ACTION, TARGET] |

注意三个"重复"：goal 在每道题的 instructions 里都完整出现；NEXT_ACTION 同时出现在 operation 头和所有目标头；combobox 的信息在 elements 和两道目标头里以不同面貌出现三次。这是无状态问答协议的代价与设计——每道题独立可读。

---

## 5. 🔁 ④ 回程翻译：从答案索引回到执行

```text
模型答案: operation="CLICK", click_target="1"
     │ validate_choice 五重校验（只批被选操作的头）
     │ targets["CLICK"]["1"]["id"]  ← 目标索引翻译回动作 id
     ▼
decision.choice = "e1"   →   agent.act 用它在 page["actions"] 查回完整动作对象执行
```

模型全程只说过"CLICK，1 号"。坐标、身份、指纹这些机械细节在回程同样不出现在模型视野里——翻译是代码单向完成的（model.py:126-133），概率分布的键也在同一处从目标索引换成动作 id。

---

## 6. 💡 设计意图

1. **上下文经济学**：考卷越小越快越便宜——中位 TypeSafe 请求仅 178ms、17 次请求共 90,558 输入 token 跑完整个 Flights 任务；裁剪掉的 rect/指纹/全量历史每一步都在为这个数字省。
2. **安全边界**：模型输出只能是候选索引；没有通道携带或影响任何执行细节（坐标/选择器/代码）。输入侧不喂机械细节，输出侧就没有机械细节可模仿。
3. **观察-决策一致性**：elements 与 criteria 由同一份快照派生，"模型看到的"与"守卫保护的"天然对齐——不存在模型认知与页面现实的第二来源。
4. **校准评估的适配**：分类器需要的是"少而干净、带当前值"的候选（choice 协议 ≤255 选项），而非全量 DOM——重组步骤就是在做这个蒸馏。

---

## 📊 总结

| 问题 | 答案 |
|------|------|
| 快照与模型输入相同吗 | 不同——隔着裁剪/重组/包装三段加工 + 回程翻译 |
| 哪些字段透传 | 仅 url/title/text（text ≤6000 字符） |
| 哪些字段被丢 | rect/node/id/marker/page_key/guards/fingerprint/screenshot/scroll/尺寸 |
| 最大的结构变化 | action_space 重组：一节点一索引、label 切分、选项摊平、controls 分离 |
| 历史怎么进模型 | 最近 10 条 × 4 字段投影（原始 20 字段账本不全发） |
| 回程怎么回到执行 | 目标索引 → targets 表查动作 id → page.actions 查回动作对象 |
| 一句话 | 快照是"观察"，action_space 把它蒸馏成"决策面"，choose 再把决策面包成"考卷" |
