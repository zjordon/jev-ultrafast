## 📋 Phase 2 — 执行决策（act）概述

> 入口: `Agent.command('act')`（agent.py 第 86-158 行），执行 `predict` 产出的决策。
> 一句话：守门 → 一次性消费 → 终态或执行 → 文本生成（如需）→ 浏览器受守卫执行——Agent 中不变量最密集的阶段。

### 🔄 主要逻辑流程

#### 1️⃣ **指纹守门与决策一次性消费** (agent.py 第 87-92, 101-104 行)
```python
if not decision or body.get("fingerprint") != page["fingerprint"]:
    raise ValueError("Observe and choose before acting")
state["decision"] = None   # Consume once, before any mutation or model call.
```
- 请求须携带与当前页一致的 fingerprint；决策在任何变更/模型调用前消费。

#### 2️⃣ **DONE 与 BLOCKED 终态处理** (agent.py 第 93-100 行)
```python
if selected in {"DONE", "BLOCKED"}:
    if not state["browser"].fresh(page):
        raise StalePage("Page changed since the decision. Choose again.")
    state["status"] = "done" if selected == "DONE" else "blocked"
```
- 终态也要新鲜度：页面已变则强迫重新决策。

#### 3️⃣ **TYPE_TEXT 文本生成与缓存** (agent.py 第 105-115 行 + model.py 第 151-198 行)
```python
if self.pending_text and self.pending_text[0] == context:
    _, text, helper = self.pending_text
else:
    text, helper = field_text(context)
    self.pending_text = (context, text, helper)
```
- fill 动作先过 fresh，再构造 context；缓存只在**整个输入相等**时复用。

#### 4️⃣ **浏览器执行与输入前守卫** (agent.py 第 116-118 行 + browser.py 第 100-107, 135-186 行)
```python
state["browser"].act(action, page, text=text)   # 内部再次 fresh + 即时几何 + 命中测试
```
- scroll/wait/click/fill/select 五种执行路径，全部零重试。

### 🔄 数据流

```
state['decision']（predict 产物）
  │
  ├── 子步骤1 → 消费后的 decision=None + action 对象 + 动作预算校验
  ├── 子步骤2 → status ∈ {done, blocked}（终态短路返回）
  ├── 子步骤3 → text（生成的或缓存的）+ text_calls 账本
  └── 子步骤4 → 浏览器输入完成 + after_input 待观察标记
```

## 返回值

执行路径最终落入 Phase 3（观察与状态更新）后返回 snapshot；终态路径直接返回 snapshot。

## 总结

1. 🔒 一次性消费从结构上杜绝双击。
2. 🛑 终态也要新鲜度——旧页面上的 DONE 不算数。
3. 💬 文本缓存键=完整输入，杜绝跨页面误用生成值。
