## `指纹守门与决策一次性消费` 方法逻辑梳理

### 📋 **方法作用**

act 的入口闸门：确认"这次执行针对的正是刚决策的那页"，随后**在任何变更或模型调用之前**把决策一次性消费掉——AGENTS.md「Never retry a browser mutation」的结构性保证。

> 源码: agent.py 第 87-92 行（守门+消费）、第 101-104 行（动作定位+预算）

---

### 🔄 **主要逻辑流程**

#### **1️⃣ 指纹守门（第 87-89 行）**

```python
decision, page = state["decision"], state["page"]
if not decision or body.get("fingerprint") != page["fingerprint"]:
    raise ValueError("Observe and choose before acting")
```

**❌ 任一失败 → ValueError：**
- `decision` 为 None：没预测过 / 已被消费 / predict 内 fresh 失败清空。
- `body.fingerprint != page.fingerprint`：调用方（检查器/脚本）手里的页面已过期，必须重新 observe+choose。
- fingerprint = sha256(url+text+actions+scroll)（browser.py 第 115-117 行），截图不参与——防"重截图导致指纹漂移"。

#### **2️⃣ 一次性消费（第 90-91 行）**

```python
# Consume once, before any mutation or model call. A retry cannot double-click.
state["decision"] = None
```

- 消费发生在**所有**可能失败的操作（文本生成、fresh、browser.act）之前——任何后续异常都无法再次进入执行路径。
- 测试 `test_stale_decision_is_consumed_before_any_mutation`：fresh=False → StalePage，且 `browser.act` 未被调用、`decision` 已为 None。

#### **3️⃣ 动作定位与动作预算（第 101-104 行）**

```python
action = next(a for a in page["actions"] if a["id"] == selected)
if len(state["history"]) >= MAX_STEPS:
    state["status"] = "blocked"
    raise ValueError(f"Stopped at the {MAX_STEPS}-action demo budget")
```

- `choice`（如 "e7"/"e12:3"/"wait"）在**观察到的** actions 里查回完整对象——查不到即 StopIteration（防御层，validate_choice 已保证 id 来自候选）。
- 60 动作预算命中时先置 blocked 再抛错——状态与异常一致。

---

### 🎯 **设计亮点**

1. **消费先行**：把"至多执行一次"从运行时约定变成时序上不可违反的顺序。
2. **双向对账**：调用方报 fingerprint、状态里存 fingerprint——两侧都必须认为"就是这页"。
3. **终态预算即 blocked**：预算耗尽是正常终局而非崩溃，检查器可正常渲染。

---

### 📊 **返回值结构**

本段无独立返回；产出 `action`（完整动作对象）供后续子步骤，`state['decision']` 恒为 None。

---

### 💡 **典型使用场景**

- 每次 act（自动 tick 或检查器确认）；重放攻击式地重复 POST 同一 act 请求会被指纹+消费双重拒绝。

---

### 🔗 **与其他方法的协作**

```
command('act')
  ├── fingerprint(page) ← browser.py
  ├── decision 消费（None）
  └── action 查找 → DONE/BLOCKED 分支 或 fill 文本生成 → browser.act
```
