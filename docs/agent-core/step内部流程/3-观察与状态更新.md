## 📋 Phase 3 — 观察与状态更新（observe）概述

> 入口: agent.py 第 119-158 行（act 尾段）+ browser.py 第 44-86 行（`Browser.observe`）。
> 一句话：先把已执行动作**不可撤销地写入账本**，再做带交互后等待的一次原子观察，最后判定页面变化与无进展。

### 🔄 主要逻辑流程

#### 1️⃣ **写前日志与耗时记录** (agent.py 第 119-141 行)
```python
state["browser"].act(action, page, text=text)
self.pending_text = None
state["elapsed_ms"] = ...
state["history"].append({..., "page_changed": None, "executed_ms": ..., "elapsed_ms": ...})
```
- 执行成功 → 清文本缓存 → 动作先入 history（`page_changed` 占位 None），**然后**才观察。

#### 2️⃣ **交互后等待与原子快照** (browser.py 第 44-86 行 + 第 188-194 行)
```python
state["page"] = state["browser"].observe(screenshot=self.screenshots)
```
- `after_input` 存在时：combobox fill 等 `role=option` 可见（≤200ms）；其余等 2 rAF 或 50ms。
- 随后单次 `Runtime.evaluate(snapshot.js)`（StalePage 重试 ≤10）→ 新 page dict（含 fingerprint）。

#### 3️⃣ **页面变化判定与无进展检测** (agent.py 第 142-158 行)
```python
state["history"][-1].update(page_changed=state["page"]["fingerprint"] != page["fingerprint"], ...)
repeated = state["history"][-3:]
state["status"] = "blocked" if len(repeated)==3 and all(
    h["page_changed"] is False and h["kind"] != "wait" for h in repeated) else "ready"
```
- 新旧 fingerprint 比对回填 `page_changed`；连续 3 步无变化且非 WAIT → blocked。

### 🔄 数据流

```
浏览器输入完成（Phase 2 产物）
  │
  ├── 子步骤1 → history[-1]（page_changed=None 占位）
  ├── 子步骤2 → 新 page（等待后的原子快照 + 可选截图/落盘）
  └── 子步骤3 → history[-1].page_changed 回填 + status ∈ {ready, blocked}
```

## 返回值

act 尾段返回 `self.snapshot()`；`run()` 检查 status 决定是否继续。

## 总结

1. 📝 写前日志：观察失败也不丢已执行动作（测试固定）。
2. ⏳ 事件感知等待：自动补全先到、模型再选——省一轮无效预测。
3. 🔁 无进展检测带 WAIT 豁免：加载等待不误杀。
