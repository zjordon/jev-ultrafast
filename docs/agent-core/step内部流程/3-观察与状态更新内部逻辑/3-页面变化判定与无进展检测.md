## `页面变化判定与无进展检测` 方法逻辑梳理

### 📋 **方法作用**

观察完成后收尾：回填 `page_changed`、刷新 URL/耗时，并做无进展检测——连续 3 步页面无变化且非等待即判定 blocked，防止 agent 在死页面上无限空转。

> 源码: agent.py 第 143-158 行

---

### 🔄 **主要逻辑流程**

#### **1️⃣ 变化回填（第 143-148 行）**

```python
state["elapsed_ms"] = round((time.perf_counter() - state["started_at"]) * 1000)
state["history"][-1].update(
    page_changed=state["page"]["fingerprint"] != page["fingerprint"],
    url=state["page"]["url"],
    elapsed_ms=state["elapsed_ms"],
)
```

- **fingerprint 比对**（sha256(url+text+actions+scroll)）：任何语义分量变化都算"页面变了"；截图不参与（动画/闪烁不误报）。
- 三态 `page_changed` 在此从 None 落定为 True/False；URL 与耗时同步刷新为观察后值。

#### **2️⃣ 无进展检测（第 153-158 行）**

```python
repeated = state["history"][-3:]
state["status"] = (
    "blocked"
    if len(repeated) == 3 and all(h["page_changed"] is False and h["kind"] != "wait" for h in repeated)
    else "ready"
)
```

**✅ 判定 blocked 需同时满足：**
1. 已有 ≥3 条 history；
2. 最近 3 条 `page_changed` 全为 **False**（注意是 False，None 不算——观察失败的那步不参与误判）；
3. 3 条 `kind` 全非 `wait`。

**❌ 任一不满足 → ready**，循环继续。

**WAIT 豁免的用意**：加载中的页面往往连续不变，模型正确地选 WAIT 等待——若不豁免，3 个 WAIT 就会被误杀。测试 `test_loading_waits_do_not_trigger_no_progress_stop`：连做 5 次 wait 决策，history=5 且 status 仍 ready。

**None 不计的用意**：`page_changed is False` 严格匹配 False——观察失败（StalePage 后 tick 恢复）的步骤保持 None，不会累积成假"无变化"。

---

### 🎯 **设计亮点**

1. **指纹级判定**：语义变化而非 DOM 事件计数——动画不漂移、无关文本不误报（与守卫哲学一致）。
2. **三态 + 类型严格**：`is False` 一词区分"看了没变"与"没看着"。
3. **blocked 是产品行为**：与 done 同级的终态，检查器正常渲染，不当作错误。

---

### 📊 **返回值结构**

`command('act')` 至此返回 `self.snapshot()`。status ∈ {ready（继续循环）, blocked（run() 退出）}。

---

### 💡 **典型使用场景**

- 每次执行后判定；典型触发：目标已达成但模型不选 DONE 而反复点击无效控件——3 步内自动止血。

---

### 🔗 **与其他方法的协作**

```
observe 新 page
  │
  ├── fingerprint(新) != fingerprint(旧) ──▶ page_changed=True
  │                                          （新元素可能出现，下一轮 predict 可见）
  └── 相等 ──▶ page_changed=False ──▶ 连续3次且非wait ──▶ blocked
                                             └─ 否则 ready ──▶ run() 继续 yield
```
