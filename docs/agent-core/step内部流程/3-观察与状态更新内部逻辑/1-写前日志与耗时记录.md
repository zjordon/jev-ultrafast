## `写前日志与耗时记录` 方法逻辑梳理

### 📋 **方法作用**

把刚执行的动作及其全部决策元数据**先于观察**写入 history 账本并记录两个时刻戳——保证任何后续观察失败都不能抹掉"动作已发生"这一事实。

> 源码: agent.py 第 118-141 行

---

### 🔄 **主要逻辑流程**

#### **1️⃣ 缓存清理与执行耗时（第 118-119 行）**

```python
state["browser"].act(action, page, text=text)
self.pending_text = None
state["elapsed_ms"] = round((time.perf_counter() - state["started_at"]) * 1000)
```

- `browser.act` 成功返回（无异常）才走到这里——**成功即弃文本缓存**，生成值永不复用到下一个字段。

#### **2️⃣ 账本写入（第 121-141 行）**

```python
state["history"].append({
    "step": len(state["history"]) + 1,
    "action": action["label"],            # 人类可读动作名
    "kind": action["kind"],               # click/fill/select/scroll/wait
    "choice": selected,                   # 动作 id
    "probability": decision["probabilities"][selected],
    "confidence": decision["confidence"],
    "latency_ms": decision["latency_ms"], # TypeSafe 延迟
    "text": text,                         # 生成的文本（若有）
    "text_helper": helper["model"] if helper else None,
    "text_latency_ms": helper["latency_ms"] if helper else 0,
    "operation": decision["operation"],
    "target": decision["target"],
    "page_changed": None,                 # 占位！观察后回填
    "url": page["url"],                   # 执行时（旧）URL
    "usage": decision["usage"],
    "executed_ms": round(...),            # 执行完成时刻
    "elapsed_ms": state["elapsed_ms"],
})
```

**关键语义：**
- `page_changed: None` 是**三态设计**：None=尚未观察 / True/False=已回填。观察抛 StalePage 时该条永远保持 None——审计可分辨"执行了但没看到结果"。
- 双时刻戳：`executed_ms`（浏览器返回）与 `elapsed_ms`（含后续开销）分离。

#### **3️⃣ 为什么必须先写后看（对照测试）**

`test_stale_observation_preserves_executed_action`（tests/test_agent.py 第 221-227 行）：
```python
runner.state["browser"].observe.side_effect = StalePage("changed")
with pytest.raises(StalePage):
    runner.command("act", ...)
assert runner.state["history"][-1]["action"] == "Go"   # 动作还在账上
runner.state["browser"].act.assert_called_once()       # 也确实只执行了一次
```

**✅ 导航在观察瞬间发生**：动作已入账，tick 捕获后重新观察——下一轮 predict 基于新页面，账本无损。
**❌ 若先观察后写**：观察抛异常会吞掉记录，出现"点击丢失"的幽灵状态。

---

### 🎯 **设计亮点**

1. **append-only 账本**：history 是唯一事实源；flights.py 直接序列化 state.json 作为运行证据。
2. **三态 page_changed**：区分"没看"与"看了没变"，审计友好的小设计。
3. **全链路延迟归档**：模型延迟、文本延迟、执行时刻齐备——performance.md 的分析数据即源于此。

---

### 📊 **返回值结构**

本段无独立返回；产出 `history[-1]`（约 20 字段）与更新后的 `elapsed_ms`。

---

### 💡 **典型使用场景**

- 每个非终态动作一次；检查器"已执行动作"列表与录制脚本的时间轴均读此账本。

---

### 🔗 **与其他方法的协作**

```
browser.act（成功）
  │
  ├── pending_text = None
  ├── history.append(...)          ← 本段
  ▼
Browser.observe ──(成功)──▶ page_changed 回填
        └──(StalePage)──▶ 账本保留 None，交给 Phase 4 恢复
```
