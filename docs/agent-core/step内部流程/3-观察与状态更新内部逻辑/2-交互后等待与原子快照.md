## `交互后等待与原子快照` 方法逻辑梳理

### 📋 **方法作用**

`Browser.observe` 的完整逻辑：先按刚执行的动作做**事件感知的短等待**（自动补全建议先到），再用**一次** `Runtime.evaluate` 原子读取整页状态（snapshot.js），失败最多重试 10 次。

> 源码: browser.py 第 44-86 行（observe）+ 第 188-194 行（observe 分支）+ agent.py 第 142-143, 149-152 行（调用点）

---

### 🔄 **主要逻辑流程**

#### **1️⃣ 交互后等待（browser.py 第 45-76 行）**

**✅ `after_input` 存在（上一动作非 wait）：**
```python
action, self.after_input = self.after_input, None   # 取走即清空
self.call("Runtime.evaluate", expression="""(action => new Promise(resolve => {
  const field=window.__jevFast?.nodes.get(action.node);
  const autocomplete=action.kind==='fill' && field?.getAttribute('role')==='combobox';
  setTimeout(finish, autocomplete ? 200 : 50);       // 硬上限
  const ready=()=>{
    const ids=(field?.getAttribute('aria-controls')||field?.getAttribute('aria-owns')||'').split(...);
    const roots=ids.length ? ids.map(id=>document.getElementById(id)).filter(Boolean) : [document];
    const options=roots.flatMap(root=>[...root.querySelectorAll('[role="option"]')]);
    if (++frames>=2 && (!autocomplete || options.some(e=>可见))) finish();   // 提前完成
    else requestAnimationFrame(ready);
  };
  requestAnimationFrame(ready);
}))(""" + json.dumps(action) + ")", awaitPromise=True, ...)
```

| 上一动作 | 等待策略 |
|----------|---------|
| combobox fill | 等待 `aria-controls/aria-owns` 指向的弹层中出现**可见** `role=option`，上限 200ms |
| 其他交互 | 2 个 rAF 或 50ms 上限 |
| wait / 无 | 不等待 |

**❌ 等待被打断**：`except RuntimeError: pass`——该 Promise 是只读探测，导航打断它无任何损失（执行已落账）。

#### **2️⃣ 原子快照（第 77-85 行 + 第 188-194 行）**

```python
for attempt in range(10):
    try:
        return browser_operation({"operation": "observe", "session": self.session, "screenshot": screenshot})
    except StalePage:
        if attempt == 9:
            raise
        time.sleep(0.02)
raise StalePage("Page did not settle")
```

`browser_operation` observe 分支：
```python
info = evaluate(READ_STATE)                    # 整个 snapshot.js 一次执行
if info is None:
    raise StalePage("Document is navigating")  # 快照开头 document.body 不存在
info["fingerprint"] = fingerprint(info)        # sha256(url+text+actions+scroll)
if request.get("screenshot", True):
    info["screenshot"] = call("Page.captureScreenshot", format="jpeg", quality=72)["data"]
return info
```

- 测试 `test_observation_is_one_atomic_browser_read` 断言 `cdp.call_count == 1` 且首个参数是 `Runtime.evaluate`——"一次浏览器调用"是契约而非巧合。
- 快照返回 null（body 为空/正在导航）→ StalePage → 重试。

#### **3️⃣ Agent 侧消费（agent.py 第 142-152 行）**

```python
state["page"] = state["browser"].observe(screenshot=self.screenshots)
```

---

### 🎯 **设计亮点**

1. **事件驱动省一轮预测**：等建议可见后再让模型从完整弹层里选——旧版不等会先选错再纠正，多付一次 TypeSafe 往返（performance.md：这是 25% 提速来源之一）。
2. **等待上限极短**：200/50ms 上限使 agent 永不为个别慢页面空转；真正加载靠 WAIT 动作显式表达。
3. **重试只重读**：10 次重试全部是只读 observe——与"变更零重试"互补，读写重试策略不对称。
4. **截图可选**：库调用默认无截图（模型不消费），检查器/录制显式开启——上下文与带宽双省。

### 📊 **返回值结构**

page dict：`{url, title, w, h, text(≤6000), scroll, actions(≤250+3), marker, page_key, guards, omitted_actions, fingerprint, screenshot?}`

### 💡 **典型使用场景**

- 每次动作后一次；构造期一次；predict 新鲜度失败时一次；tick 恢复时一次。
