## `多头响应校验与决策落账` 方法逻辑梳理

### 📋 **方法作用**

对 TypeSafe 返回的多个答案头做**选择性严格校验**（只信被选中操作的目标头），把概率分布映射回代码所有的动作 id，写入 `state['decision']` 并追加决策账本。

> 源码: model.py 第 120-148 行（`choose` 后半）+ 第 30-45 行（`validate_choice`）+ agent.py 第 77-85 行（落账）

---

### 🔄 **主要逻辑流程**

#### **1️⃣ 操作头校验（model.py 第 120-121 行）**

```python
operation_answer = validate_choice(result["answers"].get("operation", {}), operations)
operation = operation_answer["choice"]
```

#### **2️⃣ 选择性目标头校验（第 125-130 行）**

**✅ 操作属于可寻址操作（operation ∈ targets）：**
```python
target_answer = validate_choice(result["answers"].get(operation.lower() + "_target", {}), targets[operation])
target = target_answer["choice"]
choice = targets[operation][target]["id"]      # 复合索引 → 真实动作 id（如 "e7"/"e12:3"）
probabilities = {a["id"]: target_answer["probabilities"][index] ...}   # 键换成动作 id
```

**❌ 操作是控制动作/DONE/BLOCKED：**
```python
choice = controls[operation]["id"] if operation in controls else operation
probabilities[choice] = operation_answer["probabilities"][operation]
```

**📝 关键语义**：投机头（未被选操作的目标头）**根本不校验**——`test_click_cannot_consume_a_text_target` 里 click_target 选了非法 "999"，因操作选了 CLICK 而该头未被消费，整体仍通过；反之若操作头选中该操作，非法头立即 `ValueError` 拦截。

#### **3️⃣ validate_choice 五重校验（第 30-45 行）**

```python
valid = (
    answer["choice"] in ids
    and set(probabilities) == set(ids)
    and all(... math.isfinite(n) and 0 <= n <= 1 ...)
    and abs(sum(probabilities.values()) - 1) < 0.02
    and probabilities[answer["choice"]] >= max(probabilities.values()) - 1e-6
)
if not valid:
    raise ValueError("Invalid TypeSafe response; no action executed.")
```

- 拒绝：发明候选 / 概率缺失 / NaN / 越界 / 非归一 / 选了非最大项——6 种突变参数化测试覆盖。

#### **4️⃣ 决策落账（agent.py 第 77-85 行）**

```python
state["decision"] = choose(...)
state["decisions"].append({
    **state["decision"],                       # choice/operation/target/概率/usage/raw_answers/request
    "fingerprint": state["page"]["fingerprint"],
    "elapsed_ms": round((time.perf_counter() - state["started_at"]) * 1000),
})
state["status"] = "predicted"
```

---

### 🎯 **设计亮点**

1. **校验即执行边界**："no action executed" 出现在每个失败消息里——校验失败在时间上先于任何浏览器调用。
2. **id 翻译单向**：复合目标索引只在代码侧翻译回动作 id；模型侧永远看不到执行细节。
3. **账本即证据**：decisions 保存 raw_answers 与完整 request body，examples/flights.py 直接落盘供审计。

---

### 📊 **返回值结构**

`choose` 返回（同时即 `state['decision']` 初值）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `choice` | `str` | 动作 id（"e7"/"e12:3"/"wait"/"scroll_down"/"DONE"…） |
| `operation` / `target` | `str/None` | 操作名 / 目标索引（终态与控制动作为 None） |
| `probabilities` | `dict[id, float]` | 执行粒度概率（键为动作 id） |
| `operation_probabilities` / `target_probabilities` | `dict` | 两头原始分布（检查器展示用） |
| `confidence` / `target_confidence` | `float/None` | 两头置信度 |
| `latency_ms` / `usage` / `model` / `raw_answers` / `request` | — | 审计字段 |

---

### 💡 **典型使用场景**

- 每次决策一发；检查器据 `operation_probabilities`/`target_probabilities` 渲染概率条。

### 🔗 **与其他方法的协作**

```
post_json 响应

```
