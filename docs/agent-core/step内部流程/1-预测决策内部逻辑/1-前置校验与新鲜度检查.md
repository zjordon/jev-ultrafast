## `前置校验与新鲜度检查` 方法逻辑梳理

### 📋 **方法作用**

在调用模型之前完成四道闸门：会话存在、计时启动、页面新鲜（必要时重观察）、终态与决策预算拒绝——保证决策永远建立在当前真实页面上。

> 源码: agent.py 第 66-76 行（`command('predict')` 分支开头）

---

### 🔄 **主要逻辑流程**

#### **1️⃣ 会话与计时（第 66-69 行）**

```python
if not state["browser"]:
    raise ValueError("Start a demo first")
if state["started_at"] is None:
    state["started_at"] = time.perf_counter()
```

- `browser` 在 `close()` 后为 falsy → 拒绝。
- `started_at` 惰性启动：**计时从第一次预测开始**，构造期导航不计入（docs/performance.md 的计时口径与此一致）。

#### **2️⃣ 新鲜度检查（第 70-71 行）**

```python
if not state["browser"].fresh(state["page"]):
    state["page"] = state["browser"].observe(screenshot=self.screenshots)
```

- `fresh` 走全页 `marker` 比对（browser.py 第 98 行 `evaluate(MARKER) == page["marker"]`）。
- 不新鲜 → 整页重观察替换 `state['page']`；**不重试任何东西**，只是让后续决策看到新世界。
- 测试 `test_navigation_during_prediction_reobserves_without_action` 固定：此路径后 `act` 从未被调用。

#### **3️⃣ 终态与预算（第 72-76 行）**

```python
state["decision"] = None
if state["status"] in {"done", "blocked"}:
    raise ValueError("This run has stopped. Start a fresh demo.")
if len(state["decisions"]) >= MAX_STEPS * 2:
    raise ValueError("Reached the demo's model-call budget")
```

- 先清旧决策再校验——即使后面抛错，state 也不残留半决策。
- `MAX_STEPS * 2 = 120`：决策预算独立于动作预算，覆盖"决策了但没执行"的空转（如 StalePage 循环）。

---

### 🎯 **设计亮点**

1. **决策永远基于新鲜页**：predict 的第一职责是"看"，模型从不消费过期状态。
2. **预算即产品边界**：这是演示型 agent 的显式成本护栏（120 × 付费请求上限）。
3. **清空先行**：`decision=None` 在校验前执行，异常路径不产生悬挂状态。

---

### 📊 **返回值结构**

本段无独立返回；成功后进入 `choose()`。对 state 的影响：

| 字段 | 变化 |
|------|------|
| `started_at` | None → perf_counter（首次） |
| `page` | 不新鲜时被新观察替换（新 fingerprint） |
| `decision` | 置 None（等待 choose 填充） |

---

### 💡 **典型使用场景**

- 每次 tick 的第一步；检查器 Choose-next 模式下用户点击 "Predict"。

### 🔗 **与其他方法的协作**

```
command('predict')
  │
  ├── Browser.fresh(page)      ← marker 比对
  │     └── 不新鲜 → Browser.observe()
  └── 通过 → model.choose()
```
